## معرفی

پنل SE7O-SNA اینباندهای VLESS و لینک‌های اشتراک را از یک داشبورد مدیریت می‌کند. کد به‌صورت یک
بسته‌ی ماژولار نوشته شده است: پیکربندی، لایه‌ی دیتابیس، وضعیت، امنیت، مسیرها و سرویس‌های
پس‌زمینه هرکدام در ماژول خودشان قرار دارند و رابط کاربری همچنان یک قالب HTML توکار است.
استقرار ساده است — مخزن را روی Railway پوش کنید و چند متغیر محیطی تنظیم کنید. نیازی به سرور
دیتابیس، پراکسی معکوس یا خط لوله‌ی بیلد نیست.

علاوه بر خود پنل، داخل کانتینر دو ابزار اختیاری هم به‌صورت پروسه‌ی فرزند اجرا می‌شوند: پراکسی
MTProto (`mtg`) برای تلگرام، و کلاینت تونل [Aether](https://github.com/CluvexStudio/Aether) که
می‌تواند کل ترافیک خروجی کاربران را به‌جای آی‌پی خود سرور از مسیر کلودفلر عبور بدهد.

## امکانات

**کنترل دسترسی**
ورود با نام کاربری و رمز عبور، نشست JWT در کوکی HTTP-only (اعتبار ۷ روز)، محدودیت ۱۰ تلاش در
دقیقه روی مسیر ورود، سیاست رمز عبور هنگام تغییر رمز (حداقل ۸ کاراکتر شامل حرف بزرگ، حرف کوچک و
رقم) و ثبت گزارش هر تلاش ورود همراه با آی‌پی و مرورگر.

**مدیریت اینباند**
ساخت، ویرایش، فعال، غیرفعال و حذف پیکربندی‌های VLESS. تعیین سهمیه‌ی ترافیک، تاریخ انقضا و
سقف اتصال هم‌زمان برای هر اینباند. بازنویسی جداگانه‌ی path، SNI، host و اثر انگشت TLS،
افزودن بازه‌ی تکه‌تکه‌سازی بسته‌ها برای مقابله با DPI و انتخاب پرچم کشور. ساخت UUID جدید،
قطع نشست‌های زنده و دریافت JSON کلاینت برای هر اینباند. عملیات گروهی شامل فعال‌سازی، صفر کردن
مصرف و حذف است. اینباندها به صورت JSON قابل خروجی و ورودی گرفتن هستند و کل پنل را می‌توان در
یک فایل پشتیبان‌گیری و بازیابی کرد.

**آمار و تحلیل**
نمودار زنده‌ی آپلود و دانلود، تاریخچه‌ی ۲۴ ساعته با در نظر گرفتن منطقه‌ی زمانی، توزیع مصرف به
تفکیک اینباند، پیگیری سهمیه‌ی ماهانه و پایش پردازنده، حافظه و دیسک.

**فهرست آی‌پی تمیز**
افزودن، ویرایش، ورود گروهی و حذف گروهی آدرس‌های IPv4، IPv6 و نام‌های میزبان که به اشتراک‌های
تولیدشده اضافه می‌شوند. یک مجموعه‌ی پیش‌فرض در اولین اجرا اضافه می‌شود که از داشبورد قابل حذف
یا جایگزینی است.

**اشتراک و صفحه‌ی اختصاصی کاربر**
هر اینباند یک آدرس اشتراک در `/sub/{uid}` و یک صفحه‌ی عمومی در `/user/{uid}` دارد که وضعیت،
مصرف، انقضا، کد QR و دکمه‌های کپی لینک اشتراک و لینک VLESS را نشان می‌دهد — قابل اشتراک‌گذاری
با کاربر نهایی بدون دادن دسترسی به پنل.

**ترنسپورت**
WebSocket تنها ترنسپورت پشتیبانی‌شده است و روی پورت HTTPS پلتفرم اجرا می‌شود، پس نیازی به پورت
اضافه نیست.

| ترنسپورت | مسیر | توضیح |
|----------|------|-------|
| WebSocket | `/ws/{uuid}` | تنها ترنسپورت پشتیبانی‌شده. |

مسیر پیش‌فرض، اثر انگشت TLS، SNI، host و ALPN از طریق تنظیمات خروجی
(`/api/outbound-config`) قابل تغییر است.

**خروجی تونل Aether**
تب **Aether** کلاینت تونل Aether را روشن، خاموش و ری‌استارت می‌کند و فاز زنده، گیت‌وی، خروجی و
لاگ‌ها را نشان می‌دهد. Aether یک پراکسی SOCKS5 محلی روی `127.0.0.1` (به‌طور پیش‌فرض پورت
`1819`) باز می‌کند و پنل می‌تواند اتصال همه‌ی کاربران را از
آن عبور دهد. جزئیات در بخش [تونل Aether](#۶-تونل-aether-اختیاری) آمده است.

**پراکسی تلگرام (MTProxy)**
یک پراکسی MTProto با نام `mtg` به عنوان پروسه‌ی فرزند در همان کانتینر اجرا می‌شود. سکرت FakeTLS
در اولین اجرا ساخته و ذخیره می‌شود و پنل لینک `tg://proxy` را خودکار از روی آدرس TCP پلتفرم
می‌سازد. تب MTProxy وضعیت پروسه، آدرس عمومی و کد QR را نشان می‌دهد و امکان تعویض سکرت و دامنه‌ی
پوششی را می‌دهد.

**اعلان‌های تلگرام**
قالب‌های دوزبانه (انگلیسی و فارسی) برای ورود به پنل، انقضای اینباند، خطاها، هشدار ۹۰٪ سهمیه و
قطع تونل، همراه با پیش‌نمایش زنده‌ی قالب و گزارش دوره‌ای مصرف که بازه‌ی آن را از داشبورد تعیین
می‌کنید.

**زنده‌نگه‌داری**
دو حالت ساده و پیشرفته برای جلوگیری از خواب سرویس با بازه‌ی زمانی قابل تنظیم، مناسب نمونه‌هایی
که بعد از مدتی بی‌کاری متوقف می‌شوند.

## شروع سریع

### ۱. استقرار روی Railway

برای استقرار از روی تمپلت، دکمه‌ی زیر را بزنید:

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/self-hosted-panel?utm_medium=integration&utm_source=template&utm_campaign=generic)

یا به‌صورت دستی: این مخزن را به حساب گیت‌هاب خودتان فورک کنید، در Railway یک پروژه‌ی جدید از
روی فورک بسازید و بگذارید Railway آن را بیلد کند. فایل `Dockerfile` موجود به‌صورت خودکار
شناسایی می‌شود و نیازی به تعیین دستور اجرا نیست (فایل `Procfile` به‌عنوان جایگزین،
`python main.py` را اجرا می‌کند).

### ۲. پیکربندی

این متغیرهای محیطی را در تب **Variables** سرویس Railway اضافه کنید. فهرست آماده‌ی کپی همراه با
توضیح در فایل [`SE7O-SNA-config.toml`](SE7O-SNA-config.toml) هم هست.

| متغیر | ضروری | نمونه | توضیح |
|-------|-------|-------|-------|
| `ADMIN_USERNAME` | توصیه‌شده | `se7oadmin` | نام کاربری ورود به پنل. پیش‌فرض `admin` است. |
| `ADMIN_PASSWORD` | بله | `StrongPass!123` | رمز ورود پنل. اگر تنظیم نشود `admin` است، پس حتماً رمز خودتان را بگذارید. |
| `SECRET_PATH` | **بله** | `k7Qp2xVn9aTm` | پیشوند مخفی آدرس پنل مدیریت: پنل فقط روی `https://<domain>/<SECRET_PATH>/panel` در دسترس است (۳ تا ۶۴ کاراکتر: حروف انگلیسی، عدد، `-` و `_`). بدون آن، `/panel`، `/login`، `/dashboard` و API مدیریت (`/api/*`، `/stats`، `/connections`) خطای **404** می‌دهند. اگر تنظیم نشود، یک مقدار تصادفی یک‌بار ساخته، در دیتابیس ذخیره و در لاگ شروع چاپ می‌شود. |
| `SECRET_KEY` | بله | *(رشته‌ی تصادفی بلند)* | کوکی نشست JWT را امضا می‌کند. اگر تنظیم نشود، در اولین اجرا ساخته و در دیتابیس ذخیره می‌شود. |
| `DOMAIN` | توصیه‌شده | `se7o-sna.up.railway.app` | دامنه‌ی عمومی، برای ساخت درست لینک‌های اشتراک. اگر تنظیم نشود از `RAILWAY_PUBLIC_DOMAIN` در Railway خودکار تشخیص داده می‌شود. |
| `DB_PATH` | توصیه‌شده | `/data/panel.db` | محل فایل SQLite. برای حفظ داده‌ها یک Volume در Railway روی `/data` سوار کنید. |
| `DATABASE_URL` | اختیاری | `postgres://…` | رشته‌ی اتصال PostgreSQL خارجی. بر `DB_PATH` اولویت دارد. |
| `PORT` | اختیاری | `8080` | پورت گوش‌دادن. Railway مقدار خودش را تزریق می‌کند. |
| `MTPROXY_ENABLED` | اختیاری | `true` | برای اجرای پنل بدون پراکسی تلگرام روی `false` بگذارید. |
| `MTPROXY_PORT` | اختیاری | `443` | پورتی که mtg در داخل کانتینر روی آن گوش می‌دهد. همین مقدار را موقع ساخت TCP Proxy وارد می‌کنید. |
| `MTPROXY_FAKE_DOMAIN` | اختیاری | `www.cloudflare.com` | دامنه‌ای که سکرت FakeTLS خود را به جای آن جا می‌زند. |
| `MTPROXY_SECRET` | اختیاری | `ee…` | تثبیت یک سکرت مشخص به جای ساخت خودکار. |
| `MTPROXY_CONCURRENCY` | اختیاری | `4096` | بیشترین تعداد اتصال هم‌زمان MTProxy. |
| `MTPROXY_PUBLIC_HOST` | اختیاری | `shuttle.proxy.rlwy.net` | تعیین دستی میزبان عمومی، اگر خودکار تشخیص داده نشد. |
| `MTPROXY_PUBLIC_PORT` | اختیاری | `15140` | تعیین دستی پورت عمومی. |

متغیرهای مربوط به Aether همگی اختیاری هستند و در [بخش Aether](#۶-تونل-aether-اختیاری) فهرست
شده‌اند.

`ADMIN_USERNAME`، `ADMIN_PASSWORD` و `SECRET_KEY` در **هر بار** استارت‌آپ از متغیرهای محیطی
خوانده می‌شوند، نه فقط بار اول: اگر یکی را در Railway عوض کنید و دوباره دیپلوی کنید، مقدار فعلی
در دیتابیس بازنویسی می‌شود. اگر متغیری را ست نکنید، همان مقدار قبلی دیتابیس (یا در یک استقرار
کاملاً تازه، مقدار پیش‌فرض) حفظ می‌شود.

### ۳. نگهداری داده‌ها

به سرویس Railway یک Volume اضافه کنید، آن را روی `/data` سوار کنید و `DB_PATH=/data/panel.db`
را تنظیم کنید. دیتابیس SQLite، سکرت ساخته‌شده‌ی MTProxy و تنظیمات و پوشه‌ی باینری Aether همگی
زیر همین مسیر قرار می‌گیرند و بین دیپلوی‌ها حفظ می‌شوند. اگر Volume ندارید، به جای آن
`DATABASE_URL` را روی یک نمونه‌ی PostgreSQL تنظیم کنید؛ برنامه در زمان راه‌اندازی آن را تشخیص
می‌دهد و به جای SQLite استفاده می‌کند.

### ۴. فعال‌کردن پراکسی تلگرام

در تنظیمات سرویس Railway به **Networking ← TCP Proxy** بروید و پورت *داخلی* ۴۴۳ (یا هر مقداری
که برای `MTPROXY_PORT` گذاشته‌اید) را وارد کنید. Railway یک آدرس عمومی مانند
`shuttle.proxy.rlwy.net:15140` برمی‌گرداند.

کار دیگری لازم نیست. Railway دو متغیر `RAILWAY_TCP_PROXY_DOMAIN` و `RAILWAY_TCP_PROXY_PORT` را
داخل کانتینر می‌گذارد، پنل آن‌ها را می‌خواند و تب MTProxy لینک نهایی را نشان می‌دهد:

```
tg://proxy?server=shuttle.proxy.rlwy.net&port=15140&secret=ee…
```

لینک همیشه باید همین آدرس عمومی را داشته باشد. آی‌پی خود کانتینر خصوصی و از اینترنت غیرقابل
دسترس است، پس هرگز در لینک قرار نمی‌گیرد. تا وقتی TCP Proxy ساخته نشده، تب یک هشدار و یک آدرس
موقت نشان می‌دهد. اگر این متغیرها در دسترس نبودند، خودتان `MTPROXY_PUBLIC_HOST` و
`MTPROXY_PUBLIC_PORT` را تنظیم کنید.

### ۵. دامنهٔ عمومی دوم (اختیاری)

**بودجهٔ TCP Proxy روی Railway.** یک پروژهٔ Railway در حال حاضر تا ۳ TCP Proxy و ۲ دامنهٔ عمومی
برای هر سرویس اجازه می‌دهد. در این پروژه این‌طور استفاده می‌شود:

| # | برای چه | پورت داخلی | از خروجی Railway ست کنید |
|---|---|---|---|
| ۱ | MTProxy | `MTPROXY_PORT` (۴۴۳) | `MTPROXY_PUBLIC_HOST` / `MTPROXY_PUBLIC_PORT` |
| ۲ | *آزاد* | — | فعلاً توسط پنل استفاده نمی‌شود |
| ۳ | *آزاد* | — | فعلاً توسط پنل استفاده نمی‌شود |

شنوندهٔ SOCKS5 مربوط به Aether فقط روی `127.0.0.1` گوش می‌دهد، پس به TCP Proxy نیاز ندارد.

**استفاده از دامنهٔ عمومی دوم.** Railway می‌تواند یک دامنهٔ عمومی HTTP دوم هم به سرویس بدهد
(Settings ← Networking ← Public Networking ← «+ Domain»). برای این کار کد جدیدی لازم نیست — هر
لینک می‌تواند `Host`/`SNI` مخصوص خودش داشته باشد (Advanced Options، یا `custom_host`/`custom_sni`
از طریق API). کافی است لینک‌های `ws` جدید را با پرکردن همین دو فیلد به دامنهٔ دوم
بدهید؛ پنل هر دو دامنه را از همان یک پروسه سرویس می‌دهد، پس اگر یک دامنه فیلتر شد، فوراً
می‌توانید روی دامنهٔ دیگر لینک بدهید بدون اینکه چیزی را دوباره دیپلوی کنید.

### ۶. تونل Aether (اختیاری)

Aether یک کلاینت تونل مبتنی بر کلودفلر است. ایمیج Docker یک نسخه‌ی پین‌شده و تأییدشده با sha256
(`v1.5.0`، برای amd64 و arm64) را در مسیر `/usr/local/bin/aether` دارد. اگر باینری موجود نبود،
دکمه‌ی **Install** در تب Aether آن را دانلود و بررسی می‌کند.

۱. تب **Aether** را باز کنید و **Start** را بزنید. صبر کنید فاز `connected` شود.
۲. یک **Exit mode** انتخاب و ذخیره کنید:

| حالت | رفتار |
|------|-------|
| `direct` (پیش‌فرض) | اتصال‌ها مستقیم از آی‌پی سرور خارج می‌شوند، انگار Aether وجود ندارد. |
| `auto` | تا وقتی Aether وصل است از آن عبور می‌کنند؛ وگرنه مستقیم. |
| `aether` | همیشه از Aether. اگر تونل قطع باشد اتصال **رد می‌شود** (fail-closed) و آی‌پی سرور لو نمی‌رود. |

۳. در صورت تمایل **auto start** را فعال کنید تا تونل بعد از هر ری‌استارت خودکار بالا بیاید.

در همین تب می‌توانید پروتکل (`masque`، `wg`، `gool`، `mim`)، حالت اسکن
(`turbo`، `balanced`، `thorough`، `verified`، `ironclad`)، خانواده‌ی آی‌پی (`4`، `6`، `dual`)،
پروفایل noize و پورت SOCKS محلی را انتخاب کنید. (ترنسپورت HTTP/3، پراکسی HTTP روی port+1 و
دکمه‌ی Install از پنل حذف شده‌اند؛ تونل همیشه از HTTP/2 استفاده می‌کند و باینری در ایمیج Docker موجود است.) یک watchdog
سلامت تونل را از طریق پورت SOCKS5 بررسی می‌کند، با backoff نمایی ری‌استارت می‌کند و بعد از
چند استارت ناموفق پشت‌سرهم به آخرین پریست سالم برمی‌گردد. برای دریافت اعلان، رویداد
**Tunnel down** را در تب Telegram فعال کنید.

Aether فقط TCP را عبور می‌دهد؛ UDP از مسیر آن کار نمی‌کند. در حالت `aether`، تا وقتی Aether
در حال اسکن یا اتصال اولیه است، اتصال کاربران رد می‌شود.

| متغیر | پیش‌فرض | توضیح |
|-------|---------|-------|
| `AETHER_OUTBOUND` | *(تنظیم پنل)* | `direct`، `auto` یا `aether`. اگر ست شود، بر انتخاب ذخیره‌شده در پنل اولویت دارد. |
| `AETHER_AUTO_START` | *(تنظیم پنل)* | با مقدار `1`، تونل بعد از هر ری‌استارت خودکار روشن می‌شود. |
| `AETHER_BIN` | `/usr/local/bin/aether` | مسیر باینری Aether. |
| `AETHER_DIR` | `<پوشه‌ی دیتابیس>/aether` | محل فایل‌های کاری Aether و باینری دانلودشده. |
| `AETHER_VERSION` | `v1.5.0` | نسخه‌ای که دکمه‌ی **Install** داخل پنل دانلود می‌کند. |
| `WATCHDOG_TICK_SEC` | `5` | فاصله‌ی بیدار شدن حلقه‌ی watchdog. |
| `WATCHDOG_INTERVAL_SEC` | `30` | فاصله‌ی ثانیه‌ای بین بررسی‌های سلامت. |
| `WATCHDOG_MAX_FAILURES` | `3` | تعداد بررسی ناموفق پشت‌سرهم قبل از ری‌استارت. |
| `WATCHDOG_STUCK_SEC` | `300` | اگر تونل این مدت در فازی غیر از connected گیر کند، ری‌استارت می‌شود. |
| `WATCHDOG_STABLE_SEC` | `60` | مدت اتصال لازم تا یک اجرا پایدار حساب شود. |
| `WATCHDOG_FALLBACK_AFTER` | `3` | تعداد استارت ناموفق قبل از بازگشت به آخرین پریست سالم. |
| `WATCHDOG_BACKOFF_BASE_SEC` | `2` | تأخیر اولین ری‌استارت؛ با هر شکست دو برابر می‌شود. |
| `WATCHDOG_BACKOFF_MAX_SEC` | `300` | سقف تأخیر ری‌استارت. |
| `WATCHDOG_PROBE_TIMEOUT_SEC` | `10` | مهلت هر بررسی سلامت. |

توضیحات بیشتر درباره‌ی نحوه‌ی ادغام Aether در این پنل در فایل
[`AETHER-MERGE.md`](AETHER-MERGE.md) آمده است.

### ۷. ورود

آدرس `https://<دامنه‌ی-شما>/<SECRET_PATH>/panel` را باز کنید (باز کردن فقط `/<SECRET_PATH>` شما را به همان‌جا می‌برد) و با `ADMIN_USERNAME` و `ADMIN_PASSWORD` وارد
شوید. تغییر رمز از بخش **تنظیمات** بلافاصله اعمال و در دیتابیس ذخیره می‌شود — فقط مراقب باشید
متغیر `ADMIN_PASSWORD` را با مقدار قدیمی ست‌شده رها نکنید، چون در دیپلوی بعدی همان مقدار قدیمی
را روی تغییر داخل پنل بازنویسی می‌کند.

#### مسیریابی خروجی به‌ازای هر اینباند

هر اینباند تنظیم **خروجی ترافیک (Outbound)** مخصوص خودش را دارد (هنگام ایجاد/ویرایش اینباند)؛ مثلاً یک
اینباند از طریق Cloudflare WARP و اینباند دیگر مستقیم خارج می‌شود. این مقدار فقط برای همان اینباند حالت
خروج سراسری را بازنویسی می‌کند و روی اتصال‌های جدید فوراً اعمال می‌شود:

| خروجی | رفتار |
|-------|-------|
| `default` | پیروی از حالت خروج سراسری (پیش‌فرض). |
| `direct` | همیشه مستقیم از آی‌پی همین سرور. |
| `aether` (WARP) | همیشه از Aether / Cloudflare WARP. اگر تونل قطع باشد اتصال رد می‌شود (fail-closed). |
| `auto` | تا وقتی WARP وصل است از آن، وگرنه مستقیم. |
| `socks5://[user:pass@]host:port` | هر پراکسی SOCKS5 خارجی (با نام کاربری/رمز). |

#### پیدا کردن بهترین اندپوینت

تب **Best Config / بهترین کانفیگ** هر ترکیب پروتکل و حالت اسکن Aether را یکی‌یکی روی خود سرور پنل اجرا می‌کند،
چند بار تأخیر واقعی HTTPS را از داخل تونل می‌سنجد و لیست مرتب‌شده را با ms نشان می‌دهد. گزینه‌ی
**ذخیره‌ی برنده و اتصال با آن** پیش‌فرض روشن است و برنده هم به‌عنوان تنظیمات ذخیره‌شده و هم به‌عنوان
last known-good ثبت می‌شود. حین تست تونل قطع و وصل می‌شود، watchdog کنار می‌رود و Start/Restart رد می‌شود؛
با **لغو** یا Stop تونل به حالت قبل برمی‌گردد. API قدیمی `/api/endpoints/*` دست‌نخورده مانده است.

#### بررسی سلامت (Health)

`GET /health` (معادل `/api/health`) عمومی است و JSON برمی‌گرداند: وضعیت (`ok` / `degraded` / `error`)،
آپتایم، وضعیت دیتابیس، اتصال‌های فعال، وضعیت خروجی/WARP و متریک‌های سیستم (CPU، لود، حافظه، دیسک).
اگر دیتابیس در دسترس نباشد کد 503 می‌دهد؛ برای مانیتورینگ و `HEALTHCHECK` داکر مناسب است.

## اجرای محلی

```bash
pip install -r requirements.txt
DB_PATH=./panel.db ADMIN_USERNAME=admin ADMIN_PASSWORD=Test1234 python main.py
```

پنل روی `http://127.0.0.1:8080/<SECRET_PATH>/panel` در دسترس خواهد بود (مثلاً `SECRET_PATH=mysecret` بگذارید یا مقدار ساخته‌شده را از لاگ شروع بخوانید).

برای اجرای تست سرتاسری، سرور را روی پورت ۸۸۹۹ با نام کاربری `se7oadmin` و رمز `Test1234` بالا
بیاورید و این را اجرا کنید:

```bash
python smoke_test.py
```

بقیه‌ی تست‌ها نه به سرور نیاز دارند و نه به داکر:

```bash
python test_mtproxy.py
python test_upstream.py
python test_linkgen.py
python test_audit_transports.py
python test_endpoints_defined.py   # نیازمند نصب requirements
```

قیمت‌گذاری Railway را بررسی کنید. برای پیش‌بینی‌پذیر ماندن مصرف، از سهمیه‌ی هر اینباند استفاده
کنید.
